# Ускорение загрузки: что реально поможет, а что нет

## Честная оценка идеи «библиотеки с GitHub»

Готовая библиотека сама по себе не ускорит сайт. По результатам недавних замеров на production-сборке:

- Нижние фоны главной уже загружаются заранее и появляются без тёмной подложки (0 мс) на 4G — здесь ускорять нечего.
- Выбор mobile/desktop-версии, AVIF/WebP и ленивая загрузка уже работают правильно.
- Реальные оставшиеся узкие места:
  1. **Первый экран на медленной сети**: файл 165–205 КБ идёт ~1 с на 4G, до него видна тёмная подложка (FAIL в аудите).
  2. **LCP на /events ~1.1–1.6 с** из-за анимации появления картинки.
  3. **Кеширование**: сейчас медиа отдаются без агрессивных cache-заголовков — повторные визиты и переходы между страницами грузят файлы заново.

## Что предлагаю сделать (без новых тяжёлых библиотек)

1. **Кеширование медиа на уровне сервера** — добавить заголовки `Cache-Control: public, max-age=31536000, immutable` для файлов из `/media/` (имена файлов содержат версию, поэтому длинный кеш безопасен). Эффект: повторные визиты и переходы между страницами мгновенные. Библиотека не нужна — это одна настройка в отдаче статики.

2. **Мгновенный первый экран на медленной сети** — крошечная затемнённая превью-заглушка (LQIP, ~1–2 КБ, встроена прямо в разметку) под hero-картинкой: вместо чистого тёмного фона посетитель сразу видит силуэт сцены, который плавно заменяется полной картинкой. Реализуется без библиотек (data-URI + CSS), либо минимальным скриптом генерации. Утверждённые ассеты не меняются — заглушка генерируется из них.

3. **Предзагрузка hero при наведении на ссылку главной** с других страниц (опционально, нативный `<link rel="prefetch">` — тоже без библиотек).

4. **Диагностика LCP на /events**: подтвердить, что задержка — анимация появления, и предложить вариант (сократить задержку старта анимации, не убирая её). Меняется только по вашему согласию, т.к. затрагивает задуманный вид.

## Что НЕ предлагаю и почему

- **Lenis / виртуальный скролл / библиотеки предзагрузки** — уже явно запрещены концептом (нативный скролл, без hijacking), и нижние фоны уже грузятся вовремя.
- **Сервисы-оптимизаторы изображений (imgix/Cloudinary и т.п.)** — ассеты уже оптимальны (AVIF/WebP, адаптивные ширины, 13 МБ вся библиотека); внешний сервис добавит зависимость и стоимость без выигрыша.
- **Замена lazy-loading на JS-библиотеку** — недавно специально перешли на нативную ленивую загрузку браузера, она надёжнее.

## Проверка

- Повторные замеры на production-сборке (1440×900 и 390×844, с 4G и без): время до появления hero, повторный визит, переходы между страницами.
- Typecheck/build, снимки до/после, отчёт в `docs/sprint/`.

## Границы

Без публикации, без изменений БД/Auth/оплаты, утверждённых ассетов, WebGL-сцены и скролл-архитектуры. Новых runtime-зависимостей не добавляем, если не найдём конкретную необходимость.
