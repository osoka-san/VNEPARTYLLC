## Что сделаю
1. **Telegram до конца**
   - Проверю, что токен бота действителен, и получу имя бота. Токен в чат не попадёт.
   - Привязка Telegram в личном кабинете `/member`: кнопка «Привязать Telegram» для вошедшего пользователя с той же проверкой подписи. Отвязка.
   - Вход через Telegram работает только для уже одобренного участника с привязанным Telegram. Новый аккаунт при таком входе не создаётся, регистрация остаётся закрытой.
   - Понятные сообщения для случаев «Telegram не привязан», «вход устарел», «бот не настроен».
2. **База данных**
   - Устраню три оставшихся предупреждения проверки безопасности по функциям с повышенными правами. Для этого закрою прямой вызов у ролей, которым он не нужен.
   - Одобренная заявка при первом входе приглашённого автоматически связывается с его профилем: имя и Telegram переносятся из заявки.
   - Хранилище файлов не создаю: для текущих функций оно не нужно.
3. **Вход и роли**
   - В `/admin` добавлю раздел «Команда»: владелец/admin назначает или отзывает роли (admin, editor, moderator, scanner, shift_lead) уже приглашённым людям. Нужна действующая MFA-сессия, каждое действие пишется в журнал. Owner отозвать нельзя.
   - Сотрудник без настроенной MFA при заходе в `/admin` направляется на страницу MFA, а не получает отказ без объяснения.
4. **Проверки**
   - Unit-тесты привязки и назначения ролей, typecheck, lint, build.
   - Проверки базы: гость не может читать заявки и роли; пользователь без роли не может назначать роли.
   - Вход в браузере под приглашённым владельцем, если его сессия доступна. Иначе пометка NOT VERIFIED.
   - Отчёт `docs/sprint/auth-telegram-completion-report.md`.

## Что нужно от вас
- **Домен для Telegram.** В @BotFather выполнить `/setdomain` и указать домен превью (`id-preview--7e261ce4-c261-40b6-b169-b9806a6e37d7.lovable.app`), позже — опубликованный домен. Без этого Telegram не покажет кнопку входа. Сделать это за вас я не могу.
- **Первый вход владельца.** Открыть письмо-приглашение, задать пароль и подключить приложение-аутентификатор. Без этого нельзя проверить админку вживую.

## Не входит
Публикация, платежи, QR-пропуска, этапы 05+.

## Технические детали
- Привязка Telegram: server function с `requireSupabaseAuth`-эквивалентом (`getUser`), та же проверка HMAC/`auth_date`, одноразовый nonce, уникальность `profiles.telegram_id`. Обновление profile через service role только после проверки подписи.
- Роли: RPC `grant_staff_assignment` / существующий `revoke_staff_assignment`, `staff_session_ok()` + `has_role(owner|admin)`; admin не может выдать owner/admin. Только `staff_assignments`.
- Линтер: `REVOKE EXECUTE ... FROM anon, public` на SECURITY DEFINER функциях, где это возможно. `my_staff_access` остаётся доступной authenticated.
- Связь заявки и профиля: в `private.handle_new_user` подставлять display_name/telegram_username из approved `membership_requests` по `invited_user_id`.
