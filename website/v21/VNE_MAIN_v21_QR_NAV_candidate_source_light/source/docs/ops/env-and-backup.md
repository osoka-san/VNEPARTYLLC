## 4. Storage — фактическая конфигурация и проверка

**Применено в `zguyzxobplahlxuobwaw` 25.09.2026:**

| Бакет | Тип | Лимит размера | Допустимые типы | Схема пути | Доступ |
|---|---|---|---|---|---|
| `private-docs` | приватный | 2 MB | контролируется при загрузке приложением (pdf/jpeg/png) | `"<user_id>/<file>"` | только владелец пути |

Политики на `storage.objects` (в канонической миграции): чтение, загрузка, замена и удаление разрешены роли `authenticated` только когда `bucket_id = 'private-docs'` и первый сегмент пути равен `auth.uid()`. Для `anon` политик нет — доступ закрыт.

**Реальная проверка** — `docs/sprint/evidence/06/storage-private-docs.log`:
- публичный URL приватного объекта → HTTP 400 (отказ);
- запрос с publishable-ключом без сессии → 400 / `NoSuchKey`;
- загрузка с publishable-ключом → 403 `new row violates row-level security policy`;
- список бакетов анонимом → пустой массив.

Пробный объект `00000000-0000-0000-0000-000000000000/probe.txt` (47 байт) оставлен как артефакт проверки; он не принадлежит ни одному пользователю и недоступен через клиент.

**BLOCKED — публичный бакет `public-media`.** Создание публичного бакета отклонено платформой (`public_buckets_blocked`). Публичные художественные изображения продолжают отдаваться как ассеты сборки. Конфигурация публичного бакета (лимит 5 MB, `image/avif|webp|jpeg|png`, чтение всем, запись только service_role) сохранена как template в `db/migrations/20260925120100_day04_storage.sql` и применима только там, где платформа разрешает публичные бакеты. Проверка публичного бакета — NOT VERIFIED по этой причине.
