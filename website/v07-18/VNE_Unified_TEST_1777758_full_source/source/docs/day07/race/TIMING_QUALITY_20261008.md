# QA clock tolerance correction

Live TEST authenticated GET invocations observed around 11:51–11:53 UTC took approximately 374–450 ms, with some slower calls. These GETs are not QR POST RTT measurements, but demonstrate that the former 250 ms limit could reject ordinary authenticated transport. The QA-only probe bound is now 1500 ms, with maximum midpoint uncertainty ceil(RTT/2)+1 = 751 ms. This does not declare slower transport concurrent or successful.

Rehearsal evidence uses schema `day07-rehearsal-v2`. Each `browsers` entry contains exactly `dispatchedAt`, `uncertaintyMs`, and `receipt`. The coordinator copies each uncertainty from that browser's original safe report. Values must be integers from 1 through 751; the current browser also compares its value with the uncertainty captured at rehearsal dispatch. Its receipt and dispatch must still match exactly. The timing comparison is `dispatch - uncertainty <= observed`; the receipt timestamp generated by PostgreSQL must remain at or after the observation. All run/window/target/actor/correlation/receipt/PID/blocking-chain checks remain. Old schema is rejected.

The peer's bound is only a structural check. The coordinator must check both actual browser reports and actual SQL observer evidence. Client acceptance never certifies the source of evidence. Race acceptance still requires two exact PostgreSQL backend PIDs mapped to the two current actor/operation advisory keys, matching persisted receipts, one primary entry, and immutable explicit winner replay. Missing overlap remains NOT VERIFIED.

No server function, grant, account, factor, QR payload, role, database window or primary-entry invariant changes here. The 20-minute server window, fresh independent MFA/actor recheck, 15-second identity age, 30-second clock age, 4-second response fence, 10-POST budget, 1.5-second normal observer lock (under 2 seconds), cancellation/uncertainty rules, and no automatic retry are unchanged.

Local tests cover 400/900/1500 ms probes, rejection at1501 ms, real-observer-shaped overlap before estimated dispatch but within measured uncertainty, and rejection of old schema/run/receipt, duplicate PID, altered own uncertainty, out-of-range uncertainty and dispatch outside its interval. These are simulation tests, not proof of live database concurrency.
