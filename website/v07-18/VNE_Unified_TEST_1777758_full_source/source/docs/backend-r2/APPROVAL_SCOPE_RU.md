# Точная область следующего разрешения

Это подготовка к запросу разрешения, а не подтверждение применения.

Проект: закрытый TEST Supabase `xrocuwlofxhxoxajukne`.

## 1. Изменение структуры

Файл: `membership_questionnaire_proposal.sql`
SHA-256: `b7488e9a007b6dd737362621062ff8b6d54e901eadba3e79fdbcc70095921cc9`

- Дополнить существующую `membership_requests` четырьмя полями: владелец
  `owner_user_id`, полный снимок `questionnaire_snapshot` с версией, ключ повтора
  `idempotency_key`, связующий ID `correlation_id`.
- Добавить закрытые функции проверки, атомарного сохранения и чтения своих
  статусов, защиту неизменности исходных ответов/владельца/согласия.
- Заменить прежнюю уникальность email ожидающей заявки: для старых строк без
  владельца она сохраняется; для новых строк уникальность определяется аккаунтом.
  Контактный email не подтверждает личность и не связывает чужие записи.
- Старые строки не присваиваются аккаунтам и не переписываются. Новых таблиц нет.

## 2. Узкий доступ приложения

Файл: `membership_questionnaire_activation_proposal.sql`
SHA-256: `f649a44131c09ebe7c6f38dbe6e7acd4b887c292dba0681c3805b3065fe5d70d`

Создать и разрешить роли `authenticated` вызов только двух публичных операций:

- `public.vne_submit_membership_questionnaire(_command jsonb)`
- `public.vne_read_my_membership_questionnaires(_request uuid DEFAULT NULL)`

Первая сохраняет полную общую анкету и заявку своего аккаунта. Вторая возвращает
только собственные номера/статусы/версию анкеты и время отправки; содержимое
ответов, контакты и служебные заметки этот маршрут не возвращает. Владелец
определяется через `auth.uid()` и действующую сессию. При изменении данных с тем
же ключом повтора операция отклоняется, а исходные ответы не заменяются.

Это расширение доступа к сохранению анкеты, требующее отдельного подтверждения.
`anon`, `service_role`, прямые таблицы и `private`-схема новых прав не получают.

## Что это разрешение не включает

Включение флага на сайте, создание реальных пользователей, Telegram Auth,
приглашения, новые права модераторов, рассылки, допуск на событие, платежи,
production и сбор реальных анкет. Проверки после отдельного разрешения — только
на синтетических данных в указанной TEST-среде. Проверка настоящего Auth/API,
параллельных транзакций и доступного браузерного preview ещё нужна; возраст,
текст согласия и хранение реальных данных отдельно не утверждены.
