# ВНЕ — версия 19: полный исходный код в облегчённом архиве

Этот архив собран из коммита опубликованной версии 19, а не из папки со случайными локальными изменениями. Содержимое сохранённых файлов исходников не изменено.

- Версия Sites: **19**.
- Коммит: `b1a708af6838a5ff30b57ae8e305191636c5ad07`.
- Предыдущая версия: 18, `09d6bda750c2cb72a44316a623f91a774ce673f6`.
- Дата выгрузки: 6 октября 2026 года.
- Приложение: **TanStack Start + React + TypeScript + Vite**. Это не Next.js.

## За счёт чего архив облегчён

Сохранено **899 файлов исходного репозитория**. Исключены **137 файлов**, занимающих около **46,3 МБ**: первичные PNG и контрольные рендеры из `asset_log/`, исторические скриншоты из `docs/`, два файла кэша Python. Все оптимизированные изображения, шрифты и логотипы в `public/` сохранены; для обычной сборки сайта они на месте.

В архив не входят установленные зависимости `node_modules`, история `.git`, готовые сборки `dist`/`.output`, кэш и локальные секреты/состояние среды. Рабочие таблицы заявок, учётные записи и сессии не являются исходным кодом и не экспортируются.

Полный тестовый код сохранён. Для регенерации исходных изображений или сравнения с историческими визуальными эталонами потребуются исключённые оригиналы из основного репозитория. Это облегчённый исходный комплект, а не резервная копия всех исторических ассетов и данных.

## Проверить архив после распаковки

Открой терминал в папке `VNE_v19_source_light` и выполни:

```bash
python3 audit/verify_export.py
```

Ожидаемый результат: `PASS: 899 source files match VNE version 19 (...)`.

Дополнительно `SHA256SUMS.txt` содержит контрольные суммы всех файлов комплекта, кроме самого списка. На macOS:

```bash
shasum -a 256 -c SHA256SUMS.txt
```

## Сборка

Из корня `source/`, с установленными Node.js 24 и Bun:

```bash
bun install --frozen-lockfile
bun run build
```

Исходный менеджер пакетов и `bun.lock` сохранены. Не подменяй lockfile случайно созданным файлом другого менеджера. В последней проверке версии 19 использовался Node.js 24.19 и уже установленные зависимости; установку с нуля при этой выгрузке не повторяли.

Подготовить сборку для текущего размещения в Sites:

```bash
node scripts/prepare-sites-output.mjs
```

Это создаёт адаптированный Worker и статику в `dist/`. Для работающего кабинета необходимы окружение Sites, привязка базы `DB`, миграции и серверные настройки доступа. Обычный Vite dev-сервер не заменяет этот Worker и его API. `.env.example` сохранён как шаблон. Реальные значения конфигурации среды задаются отдельно.

Основной набор автоматических проверок:

```bash
node --test tests/site-member.test.mjs tests/site-requests.test.mjs tests/questionnaire.test.mjs tests/site-loading.test.mjs tests/sites-admin-gate.test.mjs tests/preview-defaults.test.mjs
```

Проверка упакованного Worker после сборки:

```bash
node scripts/verify-sites-build.mjs
```

На опубликованной версии 19 ранее пройдены TypeScript, 33 автоматические проверки и SSR-проверки 35 маршрутов. Эта выгрузка дополнительно проверяет целостность файлов и применение патча 18 → 19; она не объявляет новую браузерную проверку.

## Перенос и слияние с GitHub

1. Создай отдельную ветку в своём существующем клоне репозитория. Пример: `git switch -c import/vne-sites-v19`.
2. Определи **корень нужного приложения**. Если в репозитории несколько папок `website/v6/...`, сравни `package.json`, `vite.config.ts` и `src/`. Не переноси файлы в случайную папку.
3. Перенеси **содержимое `source/`**, включая конфигурационные файлы, в этот корень. Не вкладывай всю папку `source` как новый уровень приложения. Архив не содержит `.git`, поэтому история назначения сохранится.
4. Просмотри `git status --short` и `git diff --stat`, затем содержательные изменения через `git diff`. Не удаляй оригинальные ассеты и визуальные эталоны из своего репозитория только потому, что их нет в облегчённом архиве.
5. Установи зависимости, выполни проверки и сборку. Зафиксируй результат отдельным коммитом и отправь ветку на обычное ревью/слияние.

Если целевая ветка уже соответствует именно версии **18**, можно применить только патч `audit/V18_to_V19.patch`. В корне целевого приложения сначала проверь его:

```bash
git apply --check /absolute/path/to/VNE_v19_source_light/audit/V18_to_V19.patch
```

После успешной проверки:

```bash
git apply /absolute/path/to/VNE_v19_source_light/audit/V18_to_V19.patch
```

Замени `/absolute/path/to/` реальным путём после распаковки. Патч не является универсальным обновлением произвольной v650 или другой ветки: если исходные файлы отличаются, сначала сравни изменения и разреши конфликты. Полный снимок в `source/` остаётся эталоном версии 19.

`.openai/hosting.json` содержит идентификатор существующего проекта Sites. Он сохранён для точности снимка. Не используй этот идентификатор для регистрации другого независимого сайта; настройка нового размещения — отдельное действие.

## Основные изменения версии 19

- Настройки навбара: размеры, прозрачность, размытие, фирменные акценты, подписи и видимость ссылок; встроенный пример и сохранение.
- Голубой цвет собственного ответа с оранжевым наведением.
- Рабочий тестовый кабинет: свои заявки, статусы, история, уточнения, профиль, смена пароля и выход.
- Отдельные публичные вопросы гостю; внутренние заметки команды остаются закрытыми.
- Сохранены обязательность анкеты, до трёх ответов, числовые шкалы, выбор возраста и настройки Percent Loader.

Кабинет относится к текущим тестовым учётным записям Sites. Реальная оплата, Telegram и выпуск пропусков не подключены. Обновления кода сами по себе не создают эти интеграции и не означают допуска на событие.
