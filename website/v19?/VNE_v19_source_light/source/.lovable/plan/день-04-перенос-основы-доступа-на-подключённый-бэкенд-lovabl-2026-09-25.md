# День 04 — перенос основы доступа на подключённый бэкенд (Lovable Cloud)

## Исходное состояние
- Бэкенд Lovable Cloud включён, в нём ещё нет таблиц, функций, триггеров и хранилищ файлов.
- Этот бэкенд — отдельный проект, не xrocuwlofxhxoxajukne. Он обслуживает и предпросмотр, и будущую опубликованную версию: отдельной тестовой среды у него нет.
- Код входа сейчас читает только переменные VNE_*. Переменных VNE_* в среде нет, поэтому вход отключён (fail-closed).
- Миграции 20260925120000 и 20260925130000 проверены только на локальном PostgreSQL с заглушкой (134 PASS). На живом бэкенде они не запускались.

## Шаги
1. **Миграции.** Применить основу доступа: profiles, events, staff_assignments, applications, закрытые audit_log и outbox, RLS, REVOKE ALL и точные списки прав, функции staff_session_ok, review_application, revoke_staff_assignment, bootstrap_first_owner, my_staff_access. Хранилище файлов создать отдельно, приватным бакетом, через инструмент бакетов. Seed с выдуманными событиями не применять.
2. **Проверка после применения.** Запросами только на чтение проверить реальные права на таблицы и колонки, наличие RLS, есть ли у auth.sessions колонки user_id и not_after, а также работу linter безопасности. Отличия от заглушки исправить отдельной миграцией.
3. **Конфигурация.** Научить config.ts брать адрес и публичный ключ бэкенда из переменных Cloud (SUPABASE_URL / SUPABASE_PUBLISHABLE_KEY, VITE_*), если VNE_* не заданы. Проверки остаются: никаких sb_secret_*, только https, режим production без явного разрешения не включается. Сессия на запрос и Set-Cookie с private/no-store сохраняются.
4. **Вход.** Включить только вход по email и паролю, без автоподтверждения и без анонимных пользователей. Google добавлять только по вашему решению. MFA (TOTP) проверить на живом бэкенде.
5. **Живые проверки.** Выпустить тестовую сессию, пройти в браузере вход, выход, MFA, /member, отказ в /admin и /scan без назначения. Затем выдать назначение и проверить, что при aal2 доступ открывается. Проверить попытки подмены полей заявки гостем.
6. **Отчёт.** Обновить day-04-report.md: какие проверки пройдены на живом бэкенде, какие остались только на заглушке, что с Storage. Отметить, что xrocuwlofxhxoxajukne больше не цель, если вы это подтвердите.

## Не делаем
Операции дней 05–08, платежи, пропуска, публикацию, запуск дня 05, git sync/merge.

## Критерии готовности
- Миграции применены, linter без критических замечаний.
- Реальные права на колонки совпадают с матрицей из заглушки.
- Вход, выход, MFA и staff guard пройдены в браузере на живой сессии, есть скриншоты.
- Проверка типов, сборка и unit-тесты проходят.
