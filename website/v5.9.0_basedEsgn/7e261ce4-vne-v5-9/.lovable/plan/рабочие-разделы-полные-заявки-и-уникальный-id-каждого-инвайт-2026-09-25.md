# Рабочие «Разделы», полные заявки и уникальный ID каждого инвайта

## 1. Раздел «Разделы» в админке — рабочий
Сейчас это статичные карточки. Делаем редактор публичных текстовых блоков:
- Таблица `site_sections` (ключ раздела, заголовок, текст, статус черновик/опубликован, кто и когда изменил).
- Список разделов (Главная, События, Документы, Контакты) → карточка редактирования → «Сохранить черновик» / «Опубликовать».
- Править могут owner/admin/editor с MFA; публика читает только опубликованное; каждое изменение пишется в журнал.
- Сайт показывает опубликованный текст, при отсутствии — текущий текст по умолчанию (дизайн не меняется).

## 2. Заявки полностью
Форма /apply — быстрее и проще:
- Один экран, 3 поля (имя, email, Telegram) + согласие; подсказки прямо под полями, проверка при уходе с поля, а не только при отправке.
- Telegram: принимает `@name`, `name` и ссылку `t.me/name`, сама нормализует.
- Автозаполнение браузера, правильные клавиатуры на телефоне, Enter отправляет, фокус на первой ошибке.
- Черновик сохраняется в браузере, если закрыть вкладку.
- После отправки — понятный экран «Заявка принята» с номером заявки.

Админка → «Заявки»:
- Фильтры (ожидают / одобрены / отклонены / ошибки письма), поиск по имени, email, Telegram.
- Счётчики по статусам, дата подачи, короткий ID приглашения.
- Одобрить / Отклонить / Повторить приглашение / Отозвать неиспользованное приглашение, с подтверждением.
- История действий по заявке (кто, что, когда).

## 3. Уникальный ID каждого инвайта
- Новая таблица `invites`: собственный ID (uuid) + короткий читаемый код (например `VNE-7K3Q-9XD2`), ссылка на заявку, email, статус (создан, отправлен, ошибка, принят, отозван, истёк), срок действия, кто выдал, время отправки/принятия, число попыток.
- Каждая повторная отправка — новый инвайт с новым ID; прошлый помечается заменённым. Ничего не удаляется.
- Каждое событие инвайта пишется в существующий защищённый журнал действий с ID инвайта.
- ID передаётся в письмо (в метаданных приглашения) и фиксируется при первом входе приглашённого → статус «принят».
- Доступ к таблице: только сервер и команда owner/admin/moderator с MFA; гостям не видна.

## Технические детали
- Миграция: `invites` (+ enum статуса, уникальный `code`, индексы), `site_sections`; GRANT по шаблону, RLS; private SECURITY DEFINER функции `issue_invite`, `mark_invite_sent/failed`, `accept_invite` (вызов из auth callback), `revoke_invite`, `save_site_section`; public INVOKER-обёртки; все пишут в `private.audit_log` (object_type `invite` / `site_section`).
- `record_membership_invite` остаётся совместимым, но теперь связывает заявку с `invites.id`.
- `membership.functions.ts`: фильтры/поиск/пагинация, возврат инвайта; новые `revokeInvite`, `listRequestHistory`; `sections.functions.ts` для чтения/правки.
- Код инвайта — криптослучайный, без похожих символов, проверка уникальности в БД.
- Тесты: нормализация Telegram, генерация кода, allowlist решений, SQL-тесты прав на `invites`/`site_sections`.
- Роли, вход и Telegram-логика не меняются; публикации нет.
