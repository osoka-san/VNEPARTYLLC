## Последовательность реализации

1. **Зафиксировать baseline.** Повторно записать HEAD/branch/status и сохранить перечень изменений после `9a49e3e`; не откатывать и не менять motion/brand.
2. **Закрыть pre-import lifecycle (L1, L2, L5).** Сначала client preference gate, затем локальный loader boundary и активные таймеры. Это база для всех failure-тестов.

4. **Исправить только short-height composition (M1).** После lifecycle, чтобы измерения делались в стабильном ready. Desktop/portrait fit оставить неизменным, если regression matrix проходит.
5. **Сделать brand source воспроизводимым (B1),** не меняя утверждённые цвета; затем проверить шрифты и доступность (B2/A1).
6. **Собрать один acceptance harness (E1).** В нём состояния, reverse-scroll, restore, failure injection, resize и доказательства SVG-проекции. Никаких публичных debug URLs/query controls.

8. **GitHub — отдельная ручная операция (GH1).** Только после выбора безопасного назначения; не смешивать с кодовым патчем и не трогать существующие материалы.

## Условия приёмки этапа 01

Этап можно принять и перейти к 02 только когда:

1. Все P0 lifecycle-сценарии дают локальный static fallback без потери сайта, а normal loading не показывает assembled SVG.
2. WebGL-анимация подтверждена реальными пикселями Canvas в доступной среде; reverse-scroll, restore и hold проходят. Canvas в DOM сам по себе недостаточен.
3. Нет пересечений/обрезки на обязательных desktop, portrait mobile и short/landscape viewport; исходная геометрия не деформирована.
4. Контролируемое overlay сравнение подтверждает профили/anchors, а отличия перспективы/depth/bevel документированы.
5. Resize сохраняет логический прогресс внутри и место чтения ниже; static/dialog/orientation ветки воспроизводимы.
6. Токены синхронизируются из одного канона; Onest/Unbounded и кириллица реально подтверждены; keyboard/dialog accessibility проходит.
7. Typecheck/lint/tests/build и браузерная матрица имеют сохранённые команды, версии, exit codes, логи и state metadata, привязанные к SHA.
8. GitHub принадлежность текущего кода подтверждена точным repo/branch/SHA. Пока это **BLOCKED**, переход к 02 не объявлять полностью готовым.
9. Physical iPhone/Safari и Android могут остаться **NOT VERIFIED** и не требуют переделки без наблюдаемого дефекта; это ограничение явно остаётся в отчёте.
