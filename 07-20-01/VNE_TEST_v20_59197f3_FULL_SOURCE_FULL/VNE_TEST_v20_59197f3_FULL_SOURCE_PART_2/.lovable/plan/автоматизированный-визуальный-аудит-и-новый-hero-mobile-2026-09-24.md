# Автоматизированный визуальный аудит и новый hero mobile

## Результат

- Подключить загруженный `gallery-hero-mobile-v2.png` как новый утверждённый мобильный фон первого экрана и пересобрать его AVIF/WebP-производные без апскейла.
- Добавить воспроизводимый визуальный аудит всех пользовательских HTML-маршрутов на ширинах 360, 390, 430, 1440 и 1920 px.
- Хранить эталонные снимки и формировать снимки текущего запуска, изображения различий и машинный JSON-отчёт.

## Что будет изменено

1. **Hero mobile**
   - Заменить исходник v2 в официальной библиотеке загруженным PNG.
   - Обновить сборщик ассетов, реестр происхождения/хешей и responsive-производные.
   - Сохранить текущую typed-конфигурацию и `<picture>`; на мобильных ширинах будет выбран новый вариант.

2. **Матрица маршрутов**
   - Завести явный manifest визуального аудита для главной, каталога и двух демонстрационных событий, заявки, проекта, правил, FAQ, контактов, пяти документов и публичных оболочек `/i/:code`, `/c/:code`, `/member`, `/admin`, `/scan`.
   - Не включать машинные endpoint-ы `/mcp`, `/sitemap.xml` и `/.well-known/*`, поскольку они не являются визуальными страницами.
   - Для динамических маршрутов использовать стабильные демонстрационные значения; интерактивные состояния меню/формы останутся в существующем сценарном тесте.

3. **Снимки и сравнение**
   - Playwright будет открывать каждый маршрут в пяти фиксированных viewport, ждать шрифты/изображения и стабилизацию, отключать переходы и использовать reduced-motion для детерминированности.
   - Перед снимком проверять HTTP-статус, ошибки страницы, горизонтальный overflow и загрузку изображений.
   - Первый подтверждённый запуск создаст versioned baseline. Обычный запуск сравнит PNG попиксельно через Pillow, сохранит diff только при расхождении и завершится ошибкой выше документированного допуска.
   - Baseline не будет обновляться неявно: отдельный флаг `--update-baseline` потребует осознанного запуска.

4. **Команды и документация**
   - Добавить короткие команды package scripts для проверки и явного обновления baseline.
   - Зафиксировать структуру артефактов, порог сравнения и порядок принятия намеренных изменений в README теста.
   - Дополнить roadmap и отчёт этапа фактическими результатами без заявления о физических устройствах или production.

## Проверка

- Пересобрать галерею и подтвердить, что mobile hero использует новые байты на 360/390/430, а desktop hero не изменился.
- Создать baseline и сразу выполнить повторный regression-run по всей матрице.
- Проверить один намеренно изменённый контрольный кадр, чтобы убедиться, что diff и ненулевой exit действительно срабатывают, затем удалить искусственное изменение.
- Запустить visual audit, TypeScript, lint, brand tokens, production build и существующие route/portal проверки.
- Публикацию не выполнять.
