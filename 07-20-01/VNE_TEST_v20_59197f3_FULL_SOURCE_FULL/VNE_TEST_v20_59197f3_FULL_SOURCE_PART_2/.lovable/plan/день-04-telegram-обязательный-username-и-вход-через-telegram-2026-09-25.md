# День 04 — Telegram: обязательный @username и вход через Telegram

## Текущее состояние (проверено)
- В коде и миграциях нет ни одного упоминания Telegram: в заявке (/apply) нет поля @username, в профиле нет колонки, вход — только email + пароль + TOTP.
- Бэкенд сам по себе Telegram не поддерживает, поэтому вход делаем своими силами: официальный виджет Telegram Login и серверная проверка подписи.

## 1. Поле Telegram @username (может и должен)
- /apply: обязательное поле «Telegram» с подсказкой «например @vne_guest». Правило: 5–32 символа, латиница, цифры и `_`, начинается с буквы; ведущий `@` необязателен и сохраняется без него. Понятные ошибки на русском, доступная подпись, поле ≥44px.
- Пока заявка остаётся черновиком в памяти (demo, «Данные не отправлены»), поле проверяется только в браузере — отправку не выдумываем.
- Профиль: колонка `profiles.telegram_username` (уникальная без учёта регистра, с той же проверкой формата в базе). Пользователь может изменить только своё значение; в allowlist UPDATE добавляется только эта колонка.
- /member: показать и изменить @username; если он не заполнен — мягкое требование «Укажите Telegram», без блокировки остальных разделов.
- Тесты: unit на нормализацию и валидацию; SQL — чужой профиль не меняется, дубликат отклоняется, неверный формат отклоняется.

## 2. Вход через Telegram
```text
/login -> виджет Telegram -> данные + hash -> сервер
  -> проверка HMAC-SHA256 (ключ = SHA256(bot token)), auth_date не старше 10 мин
  -> поиск по telegram_id -> есть: сессия / нет: отказ «Аккаунт не найден» (без самостоятельной регистрации)
  -> cookie сессии (private/no-store) -> /member (safeRedirect)
```
- Кнопка «Войти через Telegram» на /login под формой email; в режиме «вход недоступен» кнопка не показывается.
- Регистрация не открывается: войти через Telegram можно только если Telegram уже привязан к существующему аккаунту. Привязка — на /member после обычного входа (тот же виджет, та же проверка, запись `telegram_id` + `telegram_username`).
- Отвязка на /member при условии, что у аккаунта есть email-вход.
- Сотрудникам /admin и /scan по-прежнему нужен TOTP (aal2): вход через Telegram даёт только уровень участника, требования к staff не ослабляются.
- Защита: проверка Origin, повторное использование одного и того же hash отклоняется, ошибки одинаковые, токен бота и данные Telegram не попадают в HTML или логи.

## 3. Что потребуется от владельца
- Бот в @BotFather: создать бота, `/setdomain` — домен предпросмотра (и позже боевой домен).
- Токен бота — сохранить через защищённую форму (секрет `TELEGRAM_BOT_TOKEN`). Коннектор Telegram не подходит: для проверки подписи нужен сам токен, а коннектор его не отдаёт.
- Имя бота (публичное) — укажу в коде.

## 4. Критерии проверки
- /apply: пустое или неверное поле блокирует «Проверить заполнение», верное проходит; без JS форма ничего не отправляет.
- SQL-матрица + живая проверка прав на новые колонки.
- Поддельный hash, устаревший auth_date, повторный hash, непривязанный Telegram — отказ; правильные данные — сессия и /member.
- Вход через Telegram не открывает /admin без TOTP.
- typecheck/lint/build без ошибок, unit PASS, отчёт дня 04 обновлён с отметкой среды. Живой виджет — NOT VERIFIED, пока нет бота и токена.

## Технические детали
- Миграция: `profiles.telegram_id bigint unique`, `telegram_username text` + check `^[A-Za-z][A-Za-z0-9_]{4,31}$` + уникальный индекс `lower(...)`; GRANT UPDATE (telegram_username) authenticated; `telegram_id` пишет только сервер. Таблица `private.telegram_login_nonce(hash, used_at)` для защиты от повтора.
- `src/lib/auth/telegram.server.ts` — проверка подписи (Web Crypto, работает на edge). `telegram.functions.ts` — `signInWithTelegram`, `linkTelegram`, `unlinkTelegram`.
- Создание сессии: после проверки сервер через админ-клиент выпускает одноразовую ссылку входа для email найденного пользователя и сразу обменивает её в request-scoped клиенте (verifyOtp token_hash) — стандартная cookie-сессия, как у email-входа.
- Виджет подключается скриптом telegram.org только на /login и /member, после гидратации.
- День 05 не затрагивается, публикации нет.
